## Objetivo
Menu de debug para o dono testar tudo do jogo. REQUISITO PRINCIPAL: remover para o deploy deve ser trivial e à prova de esquecimento.

## Arquitetura (obrigatória)
1. **Todo o código de debug em UM único arquivo novo `src/js/98-debug.js`** (ordem alfabética: depois de `90-sons.js`, antes de `99-iniciar.js`). CSS e HTML do menu criados por JS dentro desse arquivo (nada em `style.css`/`index.html`). **PROIBIDO editar qualquer outro arquivo de `src/js/`** para o debug: ganchos são feitos DENTRO do `98-debug.js` embrulhando funções globais (`const _step=step; step=function(){...}` — funções declaradas são reatribuíveis; confira com grep que o nome existe e é função global `function nome` e não `const`). Se algum gancho for impossível sem editar outro arquivo, PARE e descreva no relatório em vez de editar.
2. **`build.js`**: ler `process.argv`; sem flag → inclui `98-debug.js` (dev); com `--release` → EXCLUI `98-debug.js` do JS gerado. `--check` deve respeitar a mesma flag (`node build.js --release --check`). Atualizar o comentário de uso no topo do `build.js`. Imprimir na saída `(debug INCLUÍDO)` ou `(release, sem debug)`.
3. O arquivo começa com o comentário `// DEBUG — remova este arquivo ou rode node build.js --release`. Tudo dentro de uma IIFE `(function(){...})();` sem vazar globais (exceto o wrapper de funções necessário).
4. Defesa extra: se o arquivo for incluído por engano num deploy, o menu só abre quando `location.protocol=='file:'` ou `location.hostname` é `localhost`/`127.0.0.1`/`192.168.*` ou a URL tem `?debug`. Caso contrário o arquivo não faz nada (nenhum botão, nenhum gancho).

## Abertura e UI
- Abre/fecha com a tecla `` ` `` (Backquote) ou F2, e por um botão pequeno e discreto "DBG" (opacidade ~.35, canto inferior esquerdo ACIMA da barra de slots, sem cobrir joystick; serve no celular/APK). Painel flutuante escuro, estilo terror do jogo (fundo `#0c0c10`, borda `#4a1a1e`, texto claro), rolável, em abas: **Jogador · Itens · Inimigos · Mundo · Visual**. Fecha com a mesma tecla; NÃO pode roubar os atalhos do jogo enquanto fechado; com o painel aberto, `keydown` com foco em input do painel não dispara movimento/atalhos do jogo (use `stopPropagation` nos inputs).
- Funciona só quando o jogador é o HOST da simulação (solo ou sala própria); se `host` for falso, mostra "debug só funciona no host" e nada mais. Use as globais reais do jogo (`host`, `PL`, `id`, `IT`, `Z`, ...): confirme os nomes com grep em `src/js/` antes de usar.

## Funções do menu (mapeie cada uma lendo o código; use os helpers/estruturas que já existem, sem inventar sistemas)
**Jogador:** godmode (liga/desliga: reaplica `hp=mx` e não deixa `dead` via wrapper de `step`); vida cheia; reviver a si mesmo; +dinheiro (100/1000/10000); +nível e +XP (use a função de level-up do jogo, ex. a que gera `p.o`/opções de skill; confira); munição infinita (recarrega `s.a` no wrapper do `step`); velocidade ×1/×2/×3 (se houver campo de velocidade/boost no jogador; senão use o boost `bt` do analgésico em loop); matar/derrubar a si mesmo (testar tela de caído).
**Itens:** botões para dropar no chão, junto ao jogador, cada tipo de item (`IT.push({x,y,k,v,nt:0})`; k: 0 kit, 1 desfibrilador, 6 melhoria, 8 dinheiro com `v`, 9 bandagem, 10 analgésico, 2/3/4/5/7/11 armas conforme o mapeamento do jogo; leia `give`/`kOf`/`wiOf`/`IT3` para acertar) e "dar direto no inventário" (via `give(p,{...})` ou o equivalente) para cada um; cheat "todas as armas no nível máx" se houver caminho simples (via `give`/skill; senão pule).
**Inimigos:** spawnar na frente do jogador (~250 px): zumbi comum (k0), corredor (k1), gordão (k2), vários (×10), boss (Kraid; use a função/estado que o jogo usa para invocar o boss); matar todos os zumbis; congelar zumbis (wrapper que anula movimento/ataque ou `z.s=0`/`z.d=0` guardando o original); "zumbi não ataca" separado se for fácil; derrubar um aliado fictício a 40 px para testar o desfibrilador (cria entrada fake em `PL` só com os campos que `step`/snapshot precisam; confira `addP`; se arriscado, pule e relate).
**Mundo:** abrir/fechar a loja agora (`shopOn`, `shopX/Y` ou a função que o jogo usa); pular o relógio (+1 min, ir direto ao boss/próximo ciclo; leia como `gt`/dificuldade `dl()` são calculados e mexa só no contador que o jogo já usa); teleportar para hospital/delegacia/mercado/centro/spawn (use `BLD`/`O.B` com `T` 'h','p','m' e a porta `dx`; teleporte seguro fora de colisão); trocar de semente/regenerar mapa só se já existir caminho simples (senão pule); pausar/avançar quadro (se o `step` permitir via wrapper com flag).
**Visual:** FPS/profiler (`window.__prof=1` liga a linha `PROF ms/frame` já existente); mostrar colliders (desenhar retângulos de `O` por t, inclusive t:7, e `blk` — via wrapper de `draw` ou overlay em canvas próprio sobrepondo o `X`, sem alterar o laço principal); mostrar hitbox/raio de zumbis e jogador; mostrar contadores (zumbis vivos, `IT.length`, `DECOR.length`, `O.length`, FPS, posição x,y do jogador, tempo `gt`, dificuldade); câmera/zoom se o jogo expor `CAM` como `let` (se for `const` pule).
- Todo toggle mostra estado (ON/OFF) no botão. Estado persistente de toggles não é necessário.
